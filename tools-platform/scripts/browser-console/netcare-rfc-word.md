# RFC 方案 Word 下载浮窗（F12 测试版）

脚本：同目录 `netcare-rfc-word.js`。复制**整个文件**，不包含 Markdown 代码围栏。

## 首次使用

1. 在已经登录的 Chrome NetCare 页面打开 F12 → Console。Mac 也可用 `⌘⌥J`。
2. Console 执行上下文选择 `top`，粘贴整个 JS 文件并运行。右下角出现浮窗。
3. 输入 `NC` + 14 位数字的 RFC 单号，点击“查找并下载”。工具使用网站原生搜索和下载按钮，保留原有权限检查。
4. 首次会提示等待连接。在 Console 左上角的执行上下文下拉框选择 **`rfc-word-worker`**（URL 为 KDP 的 `PublishLiteView.html`），再次粘贴**同一个完整 JS 文件**并运行。
5. 看到“导出服务已连接”后，任务会自动继续。可切回 `top` 或关闭 F12，在浮窗连续测试其他单号。

第二次粘贴是为了在导出服务自己的域名中执行请求。NetCare 顶层无法直接访问跨域 iframe 的 JavaScript；脚本不修改浏览器安全设置。连接仅在当前页面有效，刷新或关闭浮窗后需要重新初始化。

## 行为

- 自动定位 RFC，点击原生方案下载入口；授权提示、登录过期等需要按页面提示处理后重试。
- 有多个可下载方案时，浮窗提供选择，选择后再次点击下载。
- 转换任务每 5 秒查询一次，最多等待 10 分钟。
- Word 文件在 KDP iframe 内下载，校验 DOCX 的 ZIP 文件头后触发 Chrome 保存。
- 文件名增加 RFC 单号前缀，便于区分不同作业单。
- 浮窗可拖动；“停止”停止客户端等待，不撤销服务端任务；“×”清理浮窗和连接 iframe。
- 重复粘贴会清理该上下文原有工具，再重新安装。
- 不保存密码、Cookie、Token 或单号历史，不向其他服务传输文件；请求校验值只在原导出域内使用。

## 测试范围

当前实现针对已观察到的 RFC 数字化方案 Word 导出流程。离线附件、其他 RFC 页面版本、归档单及不同导出域需要实单验证；未进入 `PublishLiteView.html` 时会停止并提示，不把其他响应当 Word 文件保存。

浮窗显示“已获取 Word 文件”表示服务端文件已返回并通过文件头检查，最终保存位置和浏览器下载许可请以 Chrome 下载记录为准。
