# 独立奖励申报与评优设计

入口：`/tools/reward-program`。本模块与“负向事件管理”的违规记录、扣罚规则和审计表完全分离；业务数据保存在当前租户的 `tools.db`。

## 四类奖励

| 类别 | 申报对象与金额 | 规则重点 |
| --- | --- | --- |
| 悬赏奖 | 项目自申报，整体金额 → 多团队 → 多成员；每层可填金额或百分比，提交时必须逐层平衡 | 项目名称、事迹、证据、团队贡献 |
| 岗位激励 | 管理员先配置固定岗位及单人金额，按周期申报人员 | 固定岗位、周期、单人金额、任职核验 |
| 操作激励 | 按专项/操作及贡献对象申报；可在规则中配置固定单人金额 | 操作标准、周期、事迹和可追溯证据 |
| 代表处评优 | 个人/团队奖项提名，逐奖项配置规则和参考预算 | 资格、评议、公示和异议处理 |

奖项默认清单以用户提供的名称为准。图片金额只作为“参考预算”显示，**不是已批准预算、可用余额或付款承诺**。当前不对年度奖池作自动占用/扣减；预算生效前应由负责人确认币种、年度额度、奖项上限及跨申请累计口径。

## 状态与权限

`草稿 → 待部门初审 → [待 AT 评议] → [公示中] → 已归档`。方括号阶段由奖项规则决定。申报人可创建、编辑和提交本人草稿；管理员记录部门/AT审批结论及公示推进。退回后申报人可修改重提；驳回后不能修改。AT 评议推进必须填写结论或会议依据。提交时保存规则快照，后续修改规则不追溯已提交申请。

公示中，登录用户可提出异议；管理员必须记录处理结论，未处理异议会阻止公示归档。公示期内的登录用户清单只显示奖项、标题和获奖名称等必要信息，不展示金额、工号、证据及内部审批日志；归档后仅申报人和管理员可查看。管理员可导出 AT 评议清单，公示清单可导出无金额 CSV。CSV 对可能被表格软件解释为公式的文本加前缀防护。

“已归档”仅表示审批与公示流程结束，**不表示财务已发放或支付成功**。实际支付、税务及会计凭证应走单独的财务流程。当前账号体系只有管理员/普通用户，AT 结论由管理员代录；如需 AT 成员独立投票、法定人数和回避，应先确定成员名单、票权及决议规则再扩展角色模型。
